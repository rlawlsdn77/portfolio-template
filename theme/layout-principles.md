# 레이아웃 원칙 (원본 · temp1 · temp2 · temp3)

> 포트폴리오 문서·발표 덱·상세 기술문서를 만들거나 고칠 때 지키는 배치 원칙입니다. 네 버전이 모두 따릅니다.
> 이 파일은 수강생의 파일입니다(`theme/`). `/portfolio-update`가 건드리지 않습니다.
> 숫자 기준은 미리보기에서 잴 수 있게 정했습니다. 확인 방법은 각 원칙 끝에 있습니다.

## 0. 바탕 원칙 (지금까지의 규칙)

| 원칙 | 내용 |
|---|---|
| 내용은 한 곳에만 | 모든 페이지가 `data/`·`src/`를 읽습니다. 페이지 파일에 글을 복사하지 않습니다. 기술 문서를 고치고 빌드하면 네 버전이 함께 바뀝니다 |
| 렌더러는 하나 | 발표 덱 네 개는 같은 렌더러(`assets/project-deck.js`)로 그립니다. 버전마다 다른 것은 나중에 싣는 CSS(temp3은 장면 밖 껍데기를 그리는 스크립트도)뿐입니다 |
| 색과 배치를 나눔 | 색·모서리·영문 글꼴(`--t-*`)은 `deck-theme.css`·`theme/theme.css`에, 구조(머리·표지·카드 배치)는 `deck-layout.css`에, 줄바꿈 규칙은 `theme/typeset.css`에 둡니다 |
| 한글 글꼴은 고정 | 한글은 늘 Pretendard입니다(덱 측정·PPTX). 버전마다 바꾸는 것은 영문 라벨 글꼴뿐입니다 |
| 크기를 바꾸면 점검 | 덱은 실제 크기를 재서 나누고 줄입니다. 배치를 바꾸면 배치 점검 `PFScene.report().audit` 0건을 확인합니다 |
| 장면 안 금지 | `vw`·`vh` 단위, 화면 폭에 따른 `@media`, `fixed`·`sticky`, 스크롤 상자, `url()` 배경 그림 |
| 장식은 화면 전용 | 책등·주사선·▶ 같은 장식은 가상 요소로 그립니다. 화면과 PDF에는 보이고 PPTX에는 들어가지 않습니다 |
| 그림 위에는 아무것도 긋지 않음 | 주사선·격자 같은 무늬는 바탕에만 깝니다(그림·코드·상자 아래). 페이지 전체를 덮는 막으로 두면 스크린샷에 검은 가로줄이 그어지고, 화면 배율 125%·150%나 덱 축소에서 줄 간격이 들쭉날쭉해집니다 |
| 그림 틀 = 그림 비율 | 대표 그림 틀은 그림 비율에 맞춥니다(덱 표지 `--ar`, 포트폴리오 `.cover`는 높이 고정 없음). 틀만 늘면 그림 위아래·양옆에 검은 띠(레터박스)가 생깁니다. 틀에 안쪽 여백을 두면(temp2 CRT) 비율은 안쪽 칸에 겁니다 |

## 1. 한 화면에 한 메시지 — 한눈에 들어오게, 넘치면 나눈다

**보는 사람이 한 화면을 읽고 "무엇을 말하는지" 바로 잡을 수 있어야 합니다.**
한 화면에 정보를 너무 많이 담으면 비교하고 따져 볼 수가 없습니다. 그래서 기준을 넘으면 **글자를 줄여 밀어 넣지 말고 나눕니다.**

### 발표 덱 — 장면 하나 = 메시지 하나

| 항목 | 기준 |
|---|---|
| 시각 자료 | 1개(화면을 나란히 비교할 때만 3개까지) |
| 요점(카드·단계) | 4개 이하 |
| 글(도입 + 요점) | 300자 안팎 |
| 코드 · 표 | 코드 20줄 안팎 · 표 6행 안팎 |
| **나누는 신호** | 넣으려고 줄여야 할 때. 코드가 원래 크기의 93% 아래(14px → 13px 미만), 다이어그램 실효 글자 10px 미만, 글자 하한(`font-floor`)에 걸림 |
| 나눈 장면의 제목 | 같은 제목을 되풀이하지 않습니다. ①·②처럼 소제목으로 구분해 무엇이 다른지 제목에서 보이게 합니다(덱 안에 같은 제목이 여럿이면 렌더러가 ①②③을 붙임) |
| 반대 방향 | 채움 40% 미만인 장면이 같은 장에 연달아 있으면 합치기를 검토합니다(한 장면이 한 메시지를 다 담지 못한 것) |

나누기·합치기는 `/portfolio-edit`(장면 카드로 확인한 뒤 `deck-edits.json`)로 합니다. 다이어그램이 너무 크면 원문에서 둘로 나눕니다.

### 발표 덱 — 게임 개발자 덱의 배치 (렌더러가 지킴)

면접에서 화면을 띄워 놓고 설명하는 덱이라 **게임 화면이 증거**이고, 길잡이 장면은 최소로 둡니다.

| 항목 | 규칙 |
|---|---|
| 길잡이 장면 | 목차 1장 + 장면이 **3개 이상인 장에만** 장 표지. 짧은 장은 장면 머리의 장 이름이 길잡이(목차·옛 주소 `#s=ch-…`는 그 장의 첫 장면으로) |
| 장 표지 | "기능 소개 장면": 장 이름 + 한 줄(포트폴리오 기능 소개와 같은 글) + 그 기능의 게임 화면 + 장면 목록. 화면이 들어가지 않으면 화면 없이 |
| 화면 모음 | 원문에서 그림만 든 표(칸마다 그림 하나)는 표가 아니라 **화면 모음**으로 크게 — 캡션은 그 열의 머리 칸 |
| 다이어그램 | 장면 색으로 그림(어두운 덱 = 어두운 판 + 강조색 테두리). 흰 상자를 띄우지 않음. 밝은 판이 필요하면 `--t-diagram` |
| 짧은 글·표 장면 | 칸이 남으면 키움 — 글만 있는 장면은 큰 글자(20px)부터, 표는 1.25배(약 19px)까지. 홀수 카드의 마지막은 두 칸을 다 씀 |

### 포트폴리오 문서 — 절 하나 = 화면 한 장

| 항목 | 기준 |
|---|---|
| 절 높이 | 데스크톱(1280×800)에서 약 1,000px(화면 1.25장) 이내 |
| 첫 화면 | 절의 제목 · 한 줄 요약 · 대표 그림 · 링크가 스크롤 없이 보임 |
| 넘칠 때 | "요약은 이 페이지, 자세히는 발표 덱·상세 문서"로 나눕니다. 카드 글은 3줄에서 자르고 [전문 보기]로 펼칩니다 |

#### temp2 — 한 장씩 넘기는 스테이지 (포트폴리오 A안)

긴 페이지를 내려 읽는 대신 **화면 한 장 = 절 하나**를 게임 스테이지처럼 넘깁니다("게임 한 판형": 타이틀 → 엔딩 크레딧).

| 항목 | 규칙 |
|---|---|
| 스테이지 | 타이틀 · 상태창(자기소개) · 스킬(기술 스택) · 월드맵(한눈에 보기) · **프로젝트마다 한 장** · 엔딩 크레딧(연락처) (프로젝트 3개면 8장) |
| 넘김(세로) | 휠·↑↓·PageUp/Down 한 번에 한 장(`scroll-snap`, 빠르게 굴려도 건너뛰지 않음). 오른쪽 아래 `STAGE 05/08 ▲ ▼`, 왼쪽 레일 = 스테이지 번호 |
| 넘김(가로) | 프로젝트 한 장 안은 **01 시작 · 02 퀘스트(기능) · 03 보스전(트러블슈팅) · 04 클리어(결과·스크린샷)** 를 ←→ 로 넘김. 보이는 길잡이 = 탭 · 막대(지금 위치) · 양옆 ◀ ▶(가로 1280 이상) · 휴대폰은 옆으로 밀기. 끝에서 더 누르면 살짝 튕김 |
| 월드맵 | 프로젝트를 기간 순서로 계단 길 위에. ←→ 로 고르면 옆 정보창이 미끄러져 바뀌고 Enter(또는 한 번 더 누르기)로 입장. **한 월드에 5개** — 6개부터 WORLD 1 · 2 …로 나뉘고 ←→ 가 월드 끝을 넘으면 다음 월드 |
| 피드백 | 픽셀 커서(누를 수 있는 곳은 초록) · 올리면 떠오르고 누르면 꺼지는 버튼 · 클릭 불꽃 · 퀘스트·메뉴의 ▶ 깜빡임 · 보스를 고르면 HP가 깎이는 연출 · 스크린샷은 올리면 아래 설명칸, 누르면 크게(←→·Esc). 움직임 줄이기 설정이면 모두 멈춤 |
| 높이 | 스테이지 = 화면 높이 − 위 메뉴 64px. **세로 750px 이상 화면에서 모든 스테이지가 한 화면에 들어가야 함**(1280×800·1366×768·1536×750·1920×1080으로 확인). 넘치면 그 장 안에서 스크롤된 뒤 다음 장 |
| 꺼지는 곳 | 가로 1024px 미만(휴대폰·태블릿) · 세로 700px 미만 · 인쇄 → 예전처럼 흐르는 페이지 |
| 연출 | 스테이지에 들어서면 절 번호가 몇 번 깜빡임. 그림·글 위에는 아무것도 얹지 않음(원칙 0) |
| 내용을 늘릴 때 | 기술 카드가 늘어 한 화면을 넘으면 스테이지를 하나 더 만듭니다. 프로젝트 안 내용이 넘치면 세부 화면(가로)을 하나 더 만듭니다(글자를 줄여 밀어 넣지 않음) |

#### temp3 — 카트리지 (아래로 읽는 한 페이지)

80년대 가정용 게임기 카트리지의 **모양**(손잡이 홈 · 오목한 라벨 창 · 아래 금속 접점 · 소프트마다 다른 껍데기 색)을 빌립니다. 실제 회사·게임기의 이름·로고·라벨 그림은 쓰지 않습니다.

| 항목 | 규칙 |
|---|---|
| 흐름 | 카트리지 한 개를 앞 → 뒤 → 속 → 소프트 목록 순으로 봄: 앞면(이름표 카트리지) · 뒷면 스티커(자기소개 원문) · 기판 위 칩(기술 하나 = 칩 하나, 근거 프로젝트 칩) · 프로젝트마다 카트리지 + 상자 뒷면 사양 · 기능 소개 · 한눈에 보기 · 연락처 |
| 프로젝트 카트리지 | 라벨 = 대표 화면(그림 비율 그대로) · 제목 · 한 줄 소개. 카트리지를 누르면 발표 덱(새 탭) — 올리면 들리며 접점이 보이고, 누르면 꽂히듯 내려감 |
| 한눈에 보기 | **카트리지 선반 + 꽂는 슬롯**: 선반의 카트리지를 누르거나(키보드 Enter) 끌어다 놓으면 슬롯에 꽂히고, 옆 칸에 그 프로젝트의 요약(제목 · 한 줄 소개 · 장르·기간 · 핵심 기술 · 역할 · 링크). 꽂은 자리는 선반에서 빈 칸. [EJECT]로 꺼냄. 처음부터 첫 프로젝트가 꽂혀 있어 누르지 않아도 요약이 보임 |
| 색 | 껍데기 색은 `temp3/carts.js`(프로젝트 순서대로 빨강 · 노랑 · 파랑 …, `BY_ID`로 고정 가능). 발표 덱도 같은 표 |
| 높이 | 1280×800에서 절마다 1,000px 이내(`T3Page.report().sections`로 잼). 기능 4개면 [발표 덱에서 보기]를 FEATURE 번호 줄에 붙여 한 줄을 아낌 |
| 주소 | 원본과 같은 절 id(`#p-<폴더>` 등). 내용을 늦게 그리므로 그린 뒤 `#절`로 이동(발표 덱의 [← 포트폴리오]가 `temp3/#p-<폴더>`) |
| PDF | [PDF로 저장] = 원본 포트폴리오 문서(`index.html`, A4 제출용)를 인쇄 |

**상세 기술문서**는 전문을 담는 곳이라 길이 제한이 없습니다. 대신 코드 한 블록은 50줄 안팎으로 두고, 절마다 첫 문단이 요약 역할을 합니다.

### 상세 기술문서 — 골라 읽기 좋게 (렌더러가 지킴)

| 항목 | 규칙 |
|---|---|
| 화면 모음 | 원문에서 그림만 든 표는 **같은 폭 격자**로(표로 그리면 머리 글 길이에 따라 그림 크기가 제각각). 휴대폰은 한 줄에 하나 |
| 코드 이름 | 인라인 코드는 낱말 경계(`ParseNetwork·Manager`, `UI·Manager`, `.`·`/` 뒤)에서만 꺾음. 숫자 뒤(`Rigidbody2D`)는 꺾지 않음 |
| 다이어그램 | 두 벌: 화면은 페이지 색(흰 상자 없음), 인쇄·밝게 읽기는 흰 판의 밝은 그림 |
| 밝게 읽기 | 어두운 페이지에 [밝게 읽기] 단추(머리 막대·휴대폰은 한눈에 상자). 코드 상자는 어두운 그대로. 고른 것은 그 브라우저에만 기억 |
| 코드 블록 | 높이 제한 없이 전부 보임(상자 안 스크롤은 접힌 "다이어그램 원문"뿐) |

**확인:** 덱은 장면마다 글자 수·요점 수·축소 배율(`[data-pf-fz]`, `.pf-zoomwrap`)과 참고 지표(`tiny-diagram`·`font-floor`·`low-fill`)로 봅니다. 포트폴리오 문서는 1280×800에서 절(`section[id]`)마다 높이를 잽니다.

## 2. 짧은 끝줄 막기 — 1~2글자 때문에 줄이 바뀌지 않게

**끝줄에 1~2글자만 떨어지면 문단이 끊겨 보이고, 표 칸은 한 줄이 늘어 높이가 들쭉날쭉해집니다.**

| 대상 | 규칙 (`theme/typeset.css`) |
|---|---|
| 문단 · 목록 · 카드 글 | `text-wrap: pretty` — 앞줄에서 낱말 하나를 내려 끝줄이 1~2글자로 남지 않게 |
| 제목 · 표 칸 · 용어 · 캡션 · 주소 | `text-wrap: balance` — 두세 줄로 꺾일 때 줄 길이를 고르게 |
| 표의 이름 칸(첫 열 · 머리 칸) | 글자 폭 최소 5em — "레드 타일", "STAGE 1"처럼 5글자 안팎의 이름이 둘로 갈라지지 않게 |
| 큰 영문 제목(temp2) | 칸 폭에 맞춰 글자 크기를 줄임(`cqi`) — "ABOUT / ME"처럼 낱말 하나만 내려가지 않게 |
| 한글 | 낱말 단위로만 꺾습니다(`word-break: keep-all`). 긴 주소·식별자만 아무 글자에서나 끊습니다 |

**CSS로 못 막는 경우는 원문에서 고칩니다.** 칸 안 낱말이 둘뿐이고 칸이 좁으면 꺾을 곳이 하나뿐입니다. 이때는 표현을 줄이거나 표 구성을 바꿉니다.

**예외(일부러 나눈 줄):** temp1 장 표지의 "CHAPTER / 01", temp2 세로 레일의 "기술 / 스택" 같은 쌓은 라벨.

**한계:** Chrome·Edge 117 이상에서 모두 동작하고, Safari·Firefox는 `balance`만 지원합니다(지원하지 않으면 예전처럼 꺾일 뿐 깨지지 않음). PPTX는 PowerPoint가 줄을 다시 바꿉니다.

**확인:** 미리보기에서 줄이 2줄 이상인 글 상자마다 끝줄 글자 수를 셉니다(1~2글자 = 걸림). 폭 1280과 375 두 가지로 봅니다.
